# Contacts paging reliability candidate 145

Scope: only native contact-group list and member loading correctness. Does not claim to implement the H5 unified contact/search/blocking feature set.

## Evidence

H5 snapshot `packages/frontend/src/pages/chat/contacts.vue:75–100` guards concurrent loading, retrieves `chat/contact-groups/list`, deduplicates group user IDs and fetches `users/show` batches. Existing native `ContactGroupView.reload` reset `ids/users/offset` while a previous `page()` could still be busy. The new first page then returned early; the stale old page could append rows and advance the reset offset. List reloads also lacked request identity, response shape validation and success clearing old errors.

## Changes

- Separate list/member read identity from mutation activity, guard session generation, cancellation and view visibility; latest refresh supersedes older reads. Leaving a page invalidates the read identity and loading state. Re-entry reloads.
- Member refresh constructs a temporary snapshot and commits only after list and first member batch succeed. Failure preserves prior visible rows and cursor. Missing group explicitly clears stale rows and disables add.
- Member pagination validates arrays and requested user IDs, restores request order even if response order differs, deduplicates group IDs, advances by requested ID count including unavailable members, and never advances on invalid response.
- Refresh may replace an in-flight read, but cannot race an active add/remove/create/rename/delete. Mutation entry invalidates prior list/member reads. After mutation the page refreshes; mutation errors are not silently hidden by successful readback.
- Loading, retry, genuine empty state and unavailable-member warning are separate. A failed refresh retries refresh; failed older page retries the same remaining IDs.
- Existing production operation scope and confirmations are unchanged. No production requests were made in preparing this candidate.

## Review / rebase onto 922316a (144)

The candidate was reapplied to 144's actual ContactsView and FixtureTransport before the new diff was generated. Latest 144 fixture changes are preserved. `git apply --check` passes against 922316a.

Review found and fixed a same-account re-entry hazard: a view's task could previously reset its mutation busy flag while a detached write was still awaiting completion. Initialisation now resets mutation identity/busy only when session generation changes. Re-entry in the same generation keeps the write locked; completion refreshes when visible. Creation's pending marker is cleared only by its matching session/operation; successful completion also clears the visible uncertainty flag. Queued mutation tasks capture the initiating generation and reject execution if it changed before they start. Reads never trigger writes or automatic mutation retries. Error retry only invokes list/user reads.
