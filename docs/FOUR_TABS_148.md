# 四栏导航改版 · build148 候选

## 状态与边界

本文件记录候选代码中的迁移，不是验收通过证明。实施基于隔离候选 `a14631d`，不覆盖 main，不创建 PR 或 release，不访问或修改生产数据。候选编译、核心单测、大小屏及深浅色 UI、真实截图和未签名 IPA 的结果，必须以对应提交的 CI 和交付清单为准。本文编写时，以下新代码尚未完成 Xcode/模拟器验证。

新底栏「消息、好友、世界圈、我的」是用户批准的导航差异。旧 H5 的内容、业务规则和功能仍须对照；不再要求旧底栏的位置一致。

## 入口迁移清单

| 原功能 | 新入口 | 保留范围 |
| --- | --- | --- |
| 私信、最近会话、已有群聊 | 消息；好友 → 已有群聊 | 复用既有会话与历史；无建群入口 |
| 用户搜索、联系人、关注/关注者、关注申请 | 好友；消息右上角 + | 延续关注/互关真实语义，不宣称微信式双向好友 |
| 动态与公开时间线 | 世界圈 → 推荐 / 关注 | 推荐使用现有 `notes/local-timeline`，关注使用 `notes/home-timeline`；无地理附近、无新推荐算法 |
| 发帖与草稿 | 世界圈右上角发帖；世界圈的频道详情 | 发布规则、附件、指定可见、投票、定时等仍用原组件；普通新帖入口只在世界圈，原帖回复/引用保留 |
| 公告与榜单面板 | 世界圈 → 发现 | 原公告、榜单详情、歌曲历史和已有管理入口保留 |
| 频道、列表、天线、剪藏、图库、热门、搜索 | 世界圈 → 发现；原更多功能入口 | 不删除旧功能；非世界圈的频道详情不显示发帖按钮 |
| 通知、提到我的、定向帖子、通知筛选 | 我的 → 通知；世界圈 → 发现 → 通知 | 保留原通知读取/已读逻辑，不用打开通知代替清除聊天未读 |
| 我的资料、我的动态、关注和关注者 | 我的 → 个人资料 / 我的动态 | 数量来自真实用户字段；不把关注数标成好友数 |
| 收藏、网盘、定时帖子 | 我的 | 原页面和业务行为保留 |
| 私信隐私、补充授权、退出、关于 | 我的 → 设置 | 原隐私和安全能力保留，不因底栏精简删除 |
| 账号与隐私设置、推送设置、多账号 | 我的 → 设置；多账号另有首页直达 | 原认证申请、隐私、通知偏好、屏蔽、账号安全、授权会话、服务连接、邀请、成就、数据迁移仍由账号设置进入 |
| 管理后台、删除账号 | 我的 → 设置 | 仍受原权限和确认流程保护 |
| Pages、Play、Deck、主题/插件等 | 更多功能 → 网页版 | 保留网页版标识，不冒充原生实现 |

原 hybrid/global 选择迁到公开推荐或关注。若服务器不允许公开时间线，则只显示关注，不伪造推荐内容。旧筛选、草稿和账号独立存储机制保留。

## 返回与账号隔离

世界圈与我的使用会话持有的独立 `NavigationPath`，支持普通二级页面与 `AppRoute` 混合导航；切栏不主动清空返回路径。通知页不再嵌套自己的 NavigationStack，而是使用来源栏的栈并显示系统返回按钮。世界圈发现页显式恢复导航栏，返回根页后由根页使用自己的标题布局。以上为源码检查结论，真实交互仍需 UI 测试确认。

根视图仍按账号 generation 重建。草稿 save/read 按 account ID 和 compose key 区分；ComposeView 拒绝将旧 owner 的草稿写入新账号。切换账号后其他页和异步响应的隔离仍须整体验证。

## 专用草稿 UI 测试

Debug 同时传 `--ui-testing --four-tabs-drafts`，且不使用 `--isolated-backend` 时：

- 只创建独立临时目录 `PUBO-FourTabs-Drafts-UITests`，每次 App 启动清空该测试目录，不碰正式草稿。
- 使用真实 ProtectedStore、JSON 编码、账号目录和草稿恢复流程，而不是内存伪装。
- 同次 App 进程内可验证：保存并关闭 → 切 TAB → 重新打开恢复；切换账号 B 为空 → 切回 A 恢复 A 草稿。
- 新的 App launch 会刻意重置测试数据，不能用此测试宣称验证了跨启动持久化。
- 其他测试仍保留原 testMode 不落盘行为；Release 不启用此开关。
