# Optional sparse World capture witness (instrumented simulator, not a performance test)

**Pinned input:** C79 `c8227e6bceb62129c018b9b3f70f5c9324a01782`. The ordinary test/production tree, required jobs, default selectors, thresholds, and default App/Core build are unchanged. There is no workflow or scheduling. All seven proposed files live under this diagnostics directory; the two Swift templates end in .inc and are not compiled by XcodeGen or SwiftPM. This is **not the same binary as C79**: the manual runner uses a temporary git archive of the exact revision and collects a source diff, its SHA-256, and old/new blob IDs. An absent/changed anchor or source hash rejects materialization before writes. The tracked checkout is only read.

## What the native experiment does, if separately run
- Dedicated Intel Xcode 26.0.1 (17A400) Mac, one new iPhone 17 Pro Max iOS 26.1 simulator, one exact XCTest, two real native drags. Existing simulator boot helper, build commands, and file/summary checks reused from the pinned archive. Ordinary release gates are not invoked or weakened.
- One in-memory, fresh-process synthetic timeline contains exactly 200 unique, fixed-width descending outer IDs. All posts include genuine nested quote/reply records sharing two fixed IDs. No nested wrapper is mistaken for a top-level reply. No network-backed route, real account, or disk-cache seeding. The XCTest sets an isolated nonce, `--ui-testing`, `--timeline-align` and the dedicated launch flag.
- On setup the normal initial load runs, then the diagnostic explicitly calls the existing `load(older:true)` nine times, in the same generation/request context. Filters, limit=20, cursor, API transport, `Records.merge`, and policy in C79 are unmodified. Capture the actual ten 20-record responses and confirm every entire merged prefix and exact cursor. Reconnect (limit 100) is not counted. **The warm-up is not proof a user scrolled ten pages.**
- The test establishes the ready/top viewport and timestamp in the real World screen, performs only the two real forward drags, stores native before/after screenshots and actual on-screen row positions, then backgrounds the app to flush bounded evidence. No programmatic setting of scroll position or visible ID count, and no probe-driven change to the actual branch. A short gesture is attributable only if observed by the existing app recognizer and bracketed by the matching native XCTest input command.
- The exact existing production callback expression is bracketed in the disposable build. The marker is set **inside the switch arm that actually ran**; it does not merely re-evaluate eligibility. The synchronous StreamClient receiver separately records its real input and the per-owner set just assigned, before cross-owner union/90-cap. Data is bounded and confined to the known synthetic IDs. Each set must match both the exhaustive original filter and an independent fixture formula. Changes after the initial viewport/within real gesture commands count; startup-only binary hits do not. Shared-child retention is reported only on a matched removal where at least one old wrapper remained. The standard synthetic setup does not connect the WebSocket, so this cannot prove delivery of subscribe/unsubscribe packets.
- Reading the state and computing a reference set adds expected observer overhead. No timing percentiles, frame times, smoothness, video behavior, physical-device result, production guarantee, or latency threshold follows. The marker/fixtures run only in a deliberately instrumented temporary Debug build. Its four altered original files are TimelineView, FixtureTransport, StreamClient and TimelineState; the two generated new source files are the probe and XCTest. The branch inputs, both return expressions, actual row callbacks, sorting/merging, owner cap, and networking implementation remain as pinned.

## Use
Python 3.11+, git, repository's normal XcodeGen/brand/dependency tooling. For an authorized **dedicated/bounded** native run on the pinned Mac, invoke:
```sh
python3 diagnostics/world-sparse/run.py --repo /path/to/pubo-ios --out /path/outside/the/checkout/new-evidence-dir
```
Creates and deletes only its new simulator and temporary source/build tree; does not install on a phone or publish. No existing evidence directory is reused. The pin must exist in the local Git object database. The checkout is not checked out, reset or cleaned. The optional Mac may need normal checked/pinned package dependencies; no setup or run was requested/offered on the user's current computer. No command is automated.
- 0 + `EXERCISED_SYNTHETIC`: actual post-baseline changed row set in the binary arm with independently verified receiver result.
- 3 + `UNEXERCISED`: valid warm fixture, real gestures and viewport advance, but no qualifying changed binary capture. Never truncate visible IDs or lower 200 to get a green result.
- Other nonzero / `UNAVAILABLE`: missing/incorrect hash, runner, method, native gesture, context, evidence, etc. A set mismatch is not marked as success. Inspect identity, native logs/xcresult, actual app receipt, and screenshot/gesture attachments before diagnosing a product issue.

Offline checks in a local exact source checkout: `python3 -m unittest discover -s diagnostics/world-sparse -p test_sparse.py -v` (or set SPARSE_BASELINE to the pinned-source directory). Synthetic validator cases prove the contract only; they are never labeled native results. No Swift compiler, Simulator, Xcode or physical device was available in the preparation environment.
